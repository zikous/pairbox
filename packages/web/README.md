# @pairbox/web

The browser app: home page, rooms, the shared editor and the terminal. Built with Svelte 5, Vite,
Tailwind and [shadcn-svelte](https://shadcn-svelte.com).

```sh
pnpm --filter @pairbox/web dev
```

## Layout

```
src/
├── pages/                 One component per route: Home, Room, NotFound
├── lib/
│   ├── api/               What the app needs from the server (types.ts)
│   │   └── fake/          A browser-only stand-in for the server
│   ├── components/
│   │   ├── ui/            shadcn-svelte components (generated, see below)
│   │   ├── brand/         Logo
│   │   ├── shared/        Small pieces used on several pages
│   │   ├── home/          Pieces of the home page
│   │   └── room/          Pieces of the room page: editor, terminal, status bar…
│   ├── router.svelte.ts   Tiny client-side router
│   └── prefs.svelte.ts    Personal preferences, saved in the browser
└── app.css                Theme colors and Tailwind setup
```

## The fake API

There is no server yet. Everything goes through the interfaces in `lib/api/types.ts`, and
`lib/api/index.ts` picks the implementation. Today that is `lib/api/fake`:

- Rooms and code are saved in `localStorage`.
- Tabs in the same browser edit together through a `BroadcastChannel`.
- The terminal is simulated per tab. Run fakes output from `print` / `console.log` lines.

Swapping in the real server means writing a new implementation of `Api` and changing one line
in `lib/api/index.ts`. Nothing in `components/` or `pages/` should change.

## UI components

`lib/components/ui/` is generated by the shadcn-svelte CLI. It is excluded from lint and
formatting so it stays easy to update. Add a component with:

```sh
pnpm dlx shadcn-svelte@latest add <name>
```

Theme colors live in `src/app.css` as CSS variables, for light and `.dark`.
